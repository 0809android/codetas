# キノコード共通AIランタイムとCODETASの境界

更新: 2026-10-05。
設計の正本: 関連リポジトリ `kinocode-ai-runner/docs/pi-runtime-architecture.md`。
共通認証・利用量契約: `kinocode-hp/docs/ai-runner/pi-runtime-integration.md`。

## 決定

- ローカルOpenCode等は `Runner /v1/* → pi-ai → モデル`。会話・コンパクション・ツール実行はローカルハーネスが管理する。
- 各サイトのチャットは `認証済みサイトバックエンド → Runner → Pi SDK → モデル`。Pi SDKはサイト単位・主体単位の会話保存とコンパクションを担当する。
- 共通本人認証、サイト権限、利用枠予約・精算、トークン消費量の正本はkinoco-apiのDB。
- CODETASは必要な場合だけモデル接続先として利用する。Piや共通認証の必須依存にはしない。

## CODETASで行わないもの

- 各サイトのログインや会員プランの判定。
- 会話IDだけを根拠にしたユーザー本人確認・他サイトの会話共有。
- 共通利用量の最終確定や、Piコンパクションの無料扱い。
- 導入を理由にした既存Gatewayの再起動・設定上書き・外部公開。

## 接続時の条件

- 上流URL・許可モデル・認証は運用設定から決める。利用者に任意URLを選ばせない。
- CODETASのキャッシュ指標は観測用。会員請求／利用制限では実測入力・出力の総数を共通台帳へ一度だけ記録する。
- CODETASの内部リトライや別モデルへの切替がある場合、複数回の上流使用量を欠落させない契約が必要。そこが未確認の経路は厳密な会員課金経路へ採用しない。
- 現在のChatGPT系Forward経路は呼出元の認証情報を必要とする。Piに置き換えても認証が不要になるわけではない。

## 今回の状態

CODETAS本体コード・実行中設定は変更しない。RunnerのPi移行と共通台帳は別リポジトリで段階実装し、既存キャッシュ改善の実測（固定IDで61.8%）とPi導入効果を混同しない。
