# Codexメンテナンス

CODETAS Desktopの「Codexメンテナンス」は、Mac版Codexのローカル状態を診断し、Codexを止めずに実行できる整理は即時、DBなど排他的な操作だけは自然終了後に自動実行する機能です。

Phase 1の診断は常に読み取り専用です。Phase 2以降の変更処理は診断とは別のジョブとして扱います。通常は「今すぐ整理」の1クリックで内部プレビューから実行まで進み、必要な場合だけ詳細プレビューを開きます。

この文書のPhase 2以降は、変更系機能が満たすべき安全契約です。実装または検証が完了していない操作は、UIで実行可能にせず、候補または実行不能理由だけを表示します。

## 構成

- `apps/desktop/src-tauri/src/maintenance.rs`
  - macOS上の診断処理
  - 外部コマンドごとのタイムアウト
  - 診断結果の集約とプライバシー処理
  - `analyze_codex_maintenance`
- `apps/desktop/src-tauri/src/maintenance_jobs.rs`
  - 変更候補のプレビューと実行計画
  - 排他ロック、バックアップ、trash、操作ジャーナル、検証、ロールバック
  - `preview_codex_maintenance`
  - `execute_codex_maintenance`
  - `list_codex_maintenance_jobs`
  - `rollback_codex_maintenance_job`
- `apps/desktop/src-tauri/src/maintenance_process.rs`
  - Codex Desktopの正常終了要求
  - Codex Desktopの明示的な再起動と起動確認
  - active writerの再検証と選択プロセスへの通常終了要求
  - `request_codex_shutdown`
  - `restart_codex`
  - `terminate_codex_writer`
- `apps/desktop/src-tauri/src/codex_app_server.rs`
  - 公式Codex App Serverプロトコルの初期化とタスク操作
  - `retry_codex_archive`
- `packages/core/src/types.ts`
  - UIとTauri間で共有する診断、プレビュー、ジョブモデル
- `apps/web/src/state.ts`
  - 診断レポート、プレビュー、ジョブ履歴のインメモリ状態
- `apps/web/src/actions.ts`
  - 診断、変更系コマンド呼び出しとJSONエクスポート
- `apps/web/src/views.ts`
  - Codex Doctorダッシュボード

既存のTauri IPCを再利用し、新しいHTTPサービスや大規模依存関係は追加していません。変更系ジョブは診断レポートと実行計画を分離します。ログは使用中・変化済みファイルをスキップし、MCP設定は最新内容を再読込して競合時に短く再試行します。SQLiteと孤立ピンは実行時点の状態を再計算します。

## Phase 1で確認する項目

- Macのディスク空き容量、データボリューム使用率
- Codex関連ディレクトリの容量、ファイル数、フォルダ数
- テキストログのうち、直近24時間に更新されたファイルの合計サイズ（増加傾向の指標）
- `~/.codex/logs_2.sqlite`の物理サイズ、ページ数、未使用ページ、回収可能容量、journal mode、読取時間
- 使用中・アーカイブ済みセッションの件数と容量
- リカバリーデータとWorktreeの容量
- セッション一覧を完全に走査できた場合だけ、孤立したピン留め候補
- `lsof`で確認できるセッションファイル保持プロセスと、公式App Serverから取得した対象スレッド名・短いプレビュー・状態
- 親プロセスが存在しないCodex CLIの孤児プロセス候補
- 直近ログに繰り返し現れる既知エラーの集計
- 設定済みMCP、認証エラー、エラー数、`mcpServerStatus/list`の最大所要時間
- 登録済みプロジェクトのGit差分規模、生成ファイル候補、upstream、origin設定
- Codex関連プロセスのCPU・メモリ、macOSのメモリ余力、スワップ

## 安全上の境界

- SQLiteは`mode=ro&immutable=1`のURI、`sqlite3 -readonly`、読取専用PRAGMAだけを使います。CodexのWAL/SHMやDBへロック・書き込みを行わず、`VACUUM`や更新PRAGMAも実行しません。起動中の最新WALを取り込まない場合があるため、値は診断時点の保守的な推定として扱います。
- セッションJSONLの会話本文は直接読みません。ファイル名からセッションIDだけを取得し、使用中ファイルとして要対応になったセッションに限り、公式App Serverの`thread/read`からスレッド名と短いプレビューを取得します。
- ログは各ファイル末尾の上限付き範囲だけを読み、既知エラーを件数へ集約します。ログ行そのものはレポートへ含めません。
- MCP設定はサーバー名だけを読み、コマンド、環境変数、トークン、認証情報は出力しません。
- Gitは`--no-optional-locks`と`core.fsmonitor=false`を適用したローカルの`status`、`diff --numstat`、設定確認だけを行い、index更新、fsmonitor hook、fetch、remote接続は実行しません。
- 外部コマンド出力は上限を設け、コマンドごとにタイムアウトします。
- ホームディレクトリ配下のパスは`~`へ正規化し、メールアドレスに見えるパス要素はマスクします。
- 一部の診断が失敗しても、残りの結果を`partialFailures`とともに返します。

孤立ピン留めは、使用中セッションとアーカイブ済みセッションの走査が完全に完了した場合だけ候補を返します。タイムアウト、読取エラー、使用中セッションディレクトリの欠落がある場合は、誤検出を避けるため判定を省略します。

## JSONエクスポート

画面の「JSONを書き出す」は、表示中の`MaintenanceReport`だけをブラウザ側でJSON化します。要対応セッションのスレッド名と短いプレビューは含まれますが、会話本文全体、ログ本文、APIキー、OAuthトークン、MCP環境変数は診断モデルへ入れません。

## Phase 2以降の変更系ジョブ

### 共通の実行契約

変更処理は、診断コマンドの副作用として実行しません。次の順序を固定します。

1. 選択内容から内部プレビューを作成する。利用者は必要に応じて対象、見込み回収量、必要空き容量、実行タイミング、バックアップ方法、実行不能理由を詳細表示できる。
2. 対象の正規化済みパス、サイズ、更新時刻などを実行計画へ記録する。
3. CODETASメンテナンス専用の排他ロックを取得する。別ジョブや不明な古いロックがある場合は停止する。
4. Codex稼働中でも安全なログ整理、選択したテキストログ退避、MCP設定変更を即時実行し、セッション・アーカイブ・リカバリー・Worktree・アプリデータ・Codex全体の退避とSQLite圧縮、孤立ピン修復は待機キューへ入れる。
5. 実行直前に対象を再検証する。ログの使用中・変化済みファイルはスキップし、MCP設定の競合は再読込して再試行する。
6. 元データをバックアップまたはCODETAS専用trashへ退避し、操作ジャーナルへ各ステップを追記する。
7. SQLiteと孤立ピン修復はCodexの自然終了を監視し、停止を検知した時点で現在値を再計算して自動実行する。
8. 成功、待機、失敗、復元結果を履歴へ残し、排他ロックを解放する。途中の一項目が失敗しても、完了済みの便利な変更を自動的に巻き戻さない。

通常実行に確認ダイアログは置きません。実行側が対象パス、シンボリックリンク、ファイルの更新状態、必要な場合のCodex停止状態、`lsof`の保持プロセス、空き容量、計画の有効期限を再確認します。会話本文、ログ本文、認証情報はジョーナルへ保存しません。

強制終了、広いglob、再帰的な即時削除、未確認の設定上書き、プロジェクトファイルの自動編集は行いません。通常終了で停止しないプロセスは、その場で失敗として報告し、強制終了は別の明示操作としても提供しません。

### ログ保持期間

テキストログの保持期間は7日、30日、90日、削除しない、から選択します。削除対象はCodexの既知ログディレクトリ配下で、保持期間より古く、実行直前の検証に一致した通常ファイルだけです。Codexの終了は要求せず、`lsof`で使用中のファイルとプレビュー後に変化したファイルをスキップします。

ファイルは即時削除せず、CODETASのメンテナンス領域にあるジョブ別trashへ移動します。同一ボリューム上のrenameを優先し、移動後の存在確認ができない場合は元ファイルを消しません。復元期限内で、元のパスが別ファイルに使われていない場合だけロールバックできます。

### SQLiteログDBのオフライン圧縮

`~/.codex/logs_2.sqlite`の圧縮は、Codex Desktop、Codex CLI、App Server、およびDB/WAL/SHMを保持するプロセスがないことを確認したオフライン状態だけで実行します。ただしCODETASから終了を要求せず、ジョブを「自然終了待ち」にして、Codexが利用者操作で終了した後に自動再開します。

安全な圧縮は次の条件を満たす必要があります。

- DB本体、WAL、SHMを同じジョブのバックアップとして保持する。
- 圧縮結果とは別に、復元可能な元DBを残す。
- 圧縮先と作業領域を限定し、見積もった出力サイズと安全余裕を満たす空き容量がなければ開始しない。
- `VACUUM INTO`などで別ファイルを生成し、元ファイルを直接更新しない。
- 圧縮後に`integrity_check`、主要テーブル、ページ数などを比較し、整合性確認後だけ原子的に切り替える。
- WAL/SHMを含む切替手順をジャーナル化し、途中終了後も次回起動時に復旧候補を提示できるようにする。
- 切替後のCodex起動確認に失敗した場合、元DBを復元できる状態を維持する。

起動中のDBに対する`VACUUM`、書込みPRAGMA、WAL削除、コピー完了前の元DB削除は行いません。

画面上では「会話コンテキストの圧縮」と「SQLiteログDBの圧縮」を別項目にします。前者はAIへ送る会話履歴、後者はMac上の未使用DBページを扱うため、同じ「圧縮」操作としてまとめません。

### 診断ストレージの選択退避

診断で表示するストレージ項目は、利用者がチェックした行だけを整理対象にできます。対象は次のとおりです。

- 使用中タスク（`~/.codex/sessions`）
- アーカイブ済みタスク（`~/.codex/archived_sessions`）
- リカバリーデータ（`~/.codex/recovery`）
- Codex Worktree（`~/.codex/worktrees`）
- Codexテキストログ（`~/Library/Logs/com.openai.codex`）
- Codexアプリデータ（`~/Library/Application Support/Codex`）

`Codex全体`（`~/.codex`）は診断表示だけです。削除対象にはできません。下位の個別項目を選んで退避します。

チェックしていない項目は診断表示だけです。実行時も即時削除せず、各ルート直下の通常ファイルと通常フォルダをジョブ別trashへ移動します。シンボリックリンク、使用中ファイル、プレビュー後に変化したファイルはスキップします。`lsof`で使用中判定ができない場合は退避しません。テキストログ以外はCodexの自然終了後に実行します。

アプリデータのブラウザキャッシュ系フォルダは除外します。テキストログ全体を選んだ場合、保存期間による部分削除は使いません。

復元は履歴から行い、元のパスが空いている場合だけ戻します。ルートフォルダ自体は消しません。

### リカバリーデータとWorktree

古いリカバリーデータとWorktreeは、容量、更新日時、登録状態、関連タスク、Git状態を確認できたものだけを整理候補として表示します。タスクIDを推定できない、Git差分がある、プロセスが保持中、登録元を完全走査できない、のいずれかでは移動を無効にします。

診断画面で利用者がチェックした場合は、上記の選択退避として専用trashへ移動できます。Worktreeに対して`git worktree remove --force`、`git clean`、ブランチ削除を自動実行しません。復元時は元のパスが空いていることを確認します。

### ピン留めとアーカイブ

タスクのアーカイブ、アーカイブ解除、その他App Serverが提供する操作は、可能な限り[公式Codex App Serverプロトコル](https://developers.openai.com/codex/app-server)を使用します。接続時は公式の初期化手順と機能ネゴシエーションを行い、未対応メソッドを推測して送信しません。

孤立ピン留めの修復は、次のすべてを満たす場合だけ候補にできます。

- 使用中セッションとアーカイブ済みセッションを完全に走査できた。
- 候補IDに対応するセッションがどちらにも存在しない。
- 対象状態ファイルの形式を認識できる。
- 実際の書換え時点でCodex関連プロセスとファイル保持プロセスが停止している。
- 元状態ファイルのバックアップ、ハッシュ、権限を保存できる。

公式APIに該当操作がない場合だけ、これらの条件を満たしたオフラインfallbackを許可します。未知のフィールドを保持した構造的編集と原子的置換を行い、形式が変化していれば拒否します。セッション走査が部分的に失敗した場合は、孤立候補を0件と断定せず、修復自体を無効にします。

active writerが原因のアーカイブ失敗では、PID、親PID、実行名、起動時刻、TTY、保持対象を表示します。利用者が選択した一致するプロセスにだけ通常終了を要求し、終了とロック解放を再確認してから、公式App Server APIでアーカイブを1回だけ再試行します。PID再利用やプロセス情報の変化を検出した場合は終了要求を送信しません。

### MCP

MCPはサーバーごとに、直近ログの起動、認証、タイムアウト、エラー回数と最大所要時間を表示します。自動修復は行わず、無効化候補を提示します。

無効化はCodex稼働中でも実行でき、選択されたサーバーだけを対象にします。毎回最新の設定を読み、Codex設定全体をバックアップしてから構造的・原子的に編集します。競合を検知した場合は最大3回再読込し、更新が続く場合だけ見送ります。コマンド、引数、環境変数、トークンは画面、レポート、ジョーナルへ出しません。ロールバックは変更後ファイルがジョブ生成物と一致する場合だけ行い、利用者の後続編集を上書きしません。

### Git

Git診断は引き続き読み取り専用です。大規模差分、生成ファイル候補、upstream未設定、origin未設定、`.gitignore`候補を表示できますが、fetch、push、commit、reset、checkout、clean、stashは実行しません。

`.gitignore`候補は提案文として表示し、プロジェクトファイルを自動編集しません。生成物かどうかはリポジトリ固有の判断が必要であり、サイズや拡張子だけで追跡対象を変更しません。

## ジョーナルとロールバック

ジョブ履歴には最低限、ジョブID、機能種別、作成・開始・終了時刻、計画の有効期限、状態、対象の正規化済み識別子、事前条件、バックアップ／trash識別子、各ステップ、検証結果、ロールバック可否を保存します。秘密情報やファイル本文は保存しません。

ロールバックは無条件の上書きではありません。対象がジョブ完了時の状態と一致すること、バックアップが検証できること、Codex停止など元操作と同等の安全条件を満たすことを再確認します。競合を検出した場合は、自動復元せず手動復旧に必要な情報だけを表示します。

自然終了待ちジョブはCODETAS起動中に定期確認し、Codex停止を検知すると自動再開します。待機中ジョブは履歴から取り消せます。この取り消しは未実行の待機項目だけを解除し、稼働中に完了したログ整理やMCP設定変更は巻き戻しません。実行中にアプリやMacが終了した場合は未完了ジャーナルとして残し、勝手に上書きやロールバックを行いません。

## CIでの検証

メンテナンスのRust単体テストはmacOSの`desktop`ジョブで`cargo test -p codetas-desktop`を実行します。既存の`cargo check --workspace`、Gatewayテスト、Webのtypecheck/buildも維持します。

開発中のローカルtest、build、lint、formatはリポジトリ方針により実行しません。検証のsource of truthはCI/CDです。変更系ジョブのテストは実ユーザーデータではなく、一時ディレクトリに作成したfixtureだけを使う必要があります。

## `/Applications/CODETAS.app`への反映

2026年8月15日の調査時点で、`/Applications/CODETAS.app`は`0.1.0`、実行バイナリの更新日時は2026年8月15日15:52:08 JSTです。これは`target/release/bundle/macos/CODETAS.app`の実行バイナリとSHA-256が一致しました。一方、Codexメンテナンスのソースは同日18:18 JST以降に更新されているため、現在インストールされているアプリには修正版が反映されていません。

現行の配布設定には次の制約があります。

- `tauri.conf.json`は`createUpdaterArtifacts: false`です。
- Updaterの静的endpointと公開鍵は空です。
- GitHub ActionsにはCIがありますが、署名・notarization・Updater artifact公開を行うrelease workflowはありません。
- インストール済みアプリはadhoc署名で、Team Identifierがありません。
- アプリ内Updaterコードは、設定された署名済みmanifestとTauri installerのバージョン、URL、サイズ、SHA-256、署名を照合しますが、配布側のendpoint、鍵、artifactがなければ更新を提供できません。

したがって、現在の0.1.0へ反映するには、次の手動配布が必要です。

1. 変更をレビューし、macOSのCIがすべて通過するまで待つ。
2. 配布担当のmacOS環境で依存関係を固定どおりに取得し、リポジトリルートから`npm run build --workspace @codetas/desktop`を実行する。
3. 生成された`target/release/bundle/macos/CODETAS.app`の識別子、バージョン、署名、実行アーキテクチャを検査する。
4. CODETAS Desktopと常駐Gatewayを正常終了する。
5. 既存の`/Applications/CODETAS.app`を日時付きバックアップとして退避し、起動確認後まで保持する。
6. 新しいapp bundleを`/Applications/CODETAS.app`へコピーする。`~/.codex`とCODETAS Application Supportは置換対象にしない。
7. CODETASを起動し、バージョン、Codexメンテナンス画面、Gatewayの起動、読み取り専用診断を確認する。
8. 起動または診断に問題があれば新bundleを終了し、退避した旧app bundleへ戻す。

この調査作業では、リポジトリ方針に従ってローカルbuildを実行せず、`/Applications/CODETAS.app`も置き換えていません。上記はCI通過後に配布担当者が実行する手順です。

公開配布では、バージョンを更新し、Apple Developer ID署名、notarization、staplingを行い、Tauri Updater artifactを生成して、既存の二重検証で参照する署名済みmanifest、installer endpoint、公開鍵を提供するrelease workflowが必要です。adhoc署名のbundleを自動更新用artifactとして公開しません。

## 障害の分類

次の2件はCodexメンテナンスの診断対象として記録しますが、今回の画像Base64入力トークン誤計算およびメンテナンス機能の変更範囲とは分離します。

- `checkout-local-branch`で失敗したworktree handoff: Git stderrがアプリログへ保存されず、`handoff_failed`と「Worktreeへの移動に失敗」だけが残る問題です。Gitコマンド実行、stderr収集、handoff状態遷移の独立課題として扱います。メンテナンスがGit stderr不足を推測で修復することはありません。
- 2026年8月15日12:42 JSTのCODETAS Desktopクラッシュ: `EXC_BAD_ACCESS`、`SIGBUS`、`KERN_MEMORY_ERROR`、main thread faultであり、クラッシュレポートは`~/Library/Logs/DiagnosticReports/Retired/codetas-desktop-2026-08-15-124239.ips`です。16:45以降の入力拒否とは時系列と故障モードが異なるため、macOSクラッシュ解析とメモリ安定性の独立課題として扱います。

これらを同じ「メンテナンス失敗」へ集約せず、画像Base64のadmission estimator修正、worktree handoffの可観測性、SIGBUSクラッシュの3系統で追跡します。
